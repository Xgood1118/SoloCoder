# 4151 - Java 工单系统

这次要做一个工单系统，Java 技术栈，主要处理客户服务和内部运维场景的工单流转。说实话工单系统看起来功能不复杂，不就是创建个工单然后让人处理吗，但实际上各种细节特别多，比如工单状态机怎么设计才能覆盖所有业务场景、跨部门协作的时候怎么通知和转派、处理时效怎么考核统计，响应速度和解决率都是客服质量的核心指标，这些都要处理得妥当才行，而且系统稳定性和数据准确性也特别重要，工单数据丢了或者错了都是大事。

工单创建的时候要支持多种来源，比如用户通过 Web 页面自助提交、客服人员在后台手动创建、系统自动创建比如监控告警触发了自动创建工单、API 接口创建比如第三方系统对接。工单要有优先级区分，紧急、重要、一般、低四档，不同优先级的工单处理要求和 SLA 时长不一样，比如紧急工单要求两小时内响应、重要工单要求四小时内响应。工单分类要做成多级树状结构，比如一级分类是技术问题，二级分类是网络问题、服务器问题、软件问题，三级分类更细，这样方便统计和派发。附件上传要支持，客户可能需要上传截图或者文档来说明问题，附件要能预览，图片直接看，文档要能下载。

状态流转要设计完整，新建、待确认、受理中、处理中、待验收、已关闭、已撤销这些状态要覆盖，状态之间的流转规则要可配置，比如处理中才能转到待验收，待验收通过才到已关闭，不能乱跳状态，配置错误要有校验。状态变更要触发事件通知，相关人员要收到提醒比如钉钉消息或者邮件，工单创建的时候要自动分配处理人。工单要能转派，就是处理人觉得这个工单不属于自己负责的范围可以转给其他人，转派的时候要填写原因，接受人也要确认是否接受，不能随意强制转派。催单功能要做，客户等不及可以催单，催单要记录次数，超过一定次数要升级给更高级别的人处理。

处理过程中要有沟通记录，处理人和客户之间的对话要能保留，工单关闭之后这些记录也要能查到，有些工单可能要保留一年以上。内部备注功能要有，就是处理过程中的内部沟通不希望让客户看到的，可以用内部备注来处理，内部备注和外部回复要区分显示。处理结果要能上传，方便客户验收的时候确认问题是否解决，解决方案要能设置让客户评价是否满意。满意度评价要做，工单关闭之后邀请客户评价，评价结果要和服务人员绩效挂钩，不满意的工单要能重新打开。协作功能要有，就是一个工单可能需要多个部门配合处理，每个部门处理自己的部分，最后汇总解决。

统计报表要有，处理量、平均处理时长、按时完成率这些指标要能统计，按时间段、按部门、按处理人等多个维度来统计，报表要能导出。SLA 监控要做，工单快超时的时候要给处理人发提醒，超时了要升级给主管，SLA 达标率要能统计。工单模板要做，常见的工单类型可以预设好处理步骤比如设备故障工单预设了需要网络组和硬件组依次处理，新建的工单可以基于模板来填充。权限控制要做，不同角色能看到和操作的范围不一样，比如客户只能看到自己的工单，客服能看到所有工单，主管能看到统计数据。数据导入导出要有，方便批量创建工单或者备份数据。单元测试要覆盖状态流转、各种业务规则校验、SLA 计算这些核心逻辑。
