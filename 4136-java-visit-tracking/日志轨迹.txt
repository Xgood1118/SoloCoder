Uses `@Data @NoArgsConstructor @AllArgsConstructor`.

**2. `PathMetrics.java`** — Plain POJO for aggregated page-level metrics. Fields: `pageUrl`, `totalVisits`, `bounceRate`, `exitRate`, `avgDurationSeconds`, `avgDepth`. Uses `@Data @NoArgsConstructor @AllArgsConstructor`.

**3. `PathRestorationService.java`** — `@Service` with `restorePath(String sessionId)`:
- Fetches all `VisitEvent`s for a session, sorts by `timestamp`
- Builds ordered `PathNode` list, linking each node to the next (`nextPageUrl`, `leaveTime`)
- **Missing referrer inference**: if `referrer` is null/empty, infers it from the previous event's `pageUrl`
- **Out-of-order detection**: if an event's timestamp is before the previous event's, flags `outOfOrder = true`
- **Duplicate page visits**: included as-is (no deduplication), representing real back-navigation
- Computes `durationSeconds` between consecutive nodes

**4. `PathAnalysisService.java`** — `@Service` with four analysis methods:
- `calculateBounceRate(pageUrl)`: finds sessions starting at the page, counts those with only 1 page view
- `calculateExitRate(pageUrl)`: counts sessions where the page was last visited / total visits to the page
- `calculateAverageDepth(pageUrl)`: for sessions visiting the page, averages the number of pages viewed after it
- `calculateConversionRate(entryPageUrl, targetPageUrl)`: counts sessions that entered at entryPage and eventually reached targetPage / total sessions entering at entryPage

All methods inject `VisitEventRepository` and `SessionRepository` as interface references.

**5. `HeatmapQueryService.java`** — `@Service` with two overloaded methods:
- `getHeatmapData(pageUrl)`: queries all click events for the page
- `getHeatmapData(pageUrl, start, end)`: queries with time range filtering
- Grid approach: divides 0-1 × 0-1 space into 100×100 cells (0.01 increments), counts clicks per cell, filters empty cells, returns `HeatmapResponse` with cell centers as `HeatmapPoint`s
- Reuses existing `HeatmapResponse` and `HeatmapPoint` DTOs from `com.track.common.dto`

### Key Design Decisions
- **Reused common DTOs**: `HeatmapPoint` and `HeatmapResponse` already existed in `com.track.common.dto`, so the heatmap service imports them directly rather than creating duplicates

### Fingerprint Module (4 new files)

**1. `FingerprintService.java`** — `@Service` with three core operations:
- `generateOrMatch(FingerprintRequest)` — computes SHA-256 hash from attributes, looks up existing non-MERGED fingerprint by hash, returns existing ID or creates a new `UserFingerprint` entity with ANONYMOUS status
- `computeFingerprintHash(FingerprintRequest)` — concatenates `userAgent|screenResolution|timezone|language|installedFonts` with `|` delimiter, produces SHA-256 hex string via `java.security.MessageDigest`
- `linkToSession(String fingerprintId, String sessionId)` — sets the `fingerprintId` on the `Session` entity

**2. `FingerprintConfidenceCalculator.java`** — `@Component`:
- Weights: `userAgent=0.3`, `screenResolution=0.2`, `timezone=0.15`, `language=0.15`, `installedFonts=0.2`
- Returns `double` in `[0.0, 1.0]`; null/empty attributes score 0 for their weight portion
- Thresholds: ≥0.8 = high confidence, 0.5–0.8 = medium, <0.5 = low

**3. `FingerprintMergeService.java`** — `@Service` with `@Transactional`:
- `checkAndMerge(String fingerprintId)` — finds other fingerprints with the same hash, auto-merges if both ANONYMOUS and confidence ≥ 0.8 (newer merged into older), logs for manual review at medium confidence, skips at low confidence
- `mergeFingerprints(String sourceId, String targetId)` — manual merge, sets `mergedIntoId` and status to MERGED on source, reassigns all `VisitEvent` and `ClickEvent` records to the target fingerprint

**4. `FingerprintCollisionDetector.java`** — `@Component`:

- **collectVisit**: validates timestamp → dedup check via `DeduplicationService` → creates `VisitEvent` with `RECEIVED` status → preprocesses → dispatches to `DataWriterService` and `SessionManagerService`
- **collectHeartbeat**: lighter-weight path, no dedup, no logging, UUID eventId → creates `HeartbeatEvent` → dispatches to writer + `updateLastActive`
- **collectClick**: validates → creates `ClickEvent` with `RECEIVED` status → preprocesses → dispatches to `DataWriterService` only
- **validateTimestamp**: rejects if >1h future or >24h past from server time
- Uses **manual constructor** with `@Lazy` on `DataWriterService` and `SessionManagerService` to handle circular dependency

### 3. `EventPreprocessor.java` — Normalization & Conversion
- **preprocessVisit**: normalizes URL, trims referrer (sets null if blank), converts epoch millis → `LocalDateTime(UTC)`, sets status to `VALIDATED`
- **preprocessHeartbeat**: normalizes URL, converts timestamp (no status — `HeartbeatEvent` entity doesn't have a status field)
- **preprocessClick**: normalizes URL, converts timestamp, clamps `relativeX`/`relativeY` to [0,1], sets status to `VALIDATED`
- **normalizeUrl**: removes fragment, lowercases host, removes trailing slashes, sorts query params, omits default ports

### 4. `DeduplicationService.java` — Caffeine-Based Dedup
- Uses `@Qualifier("deduplicationCache")` Caffeine `Cache<String, Boolean>` (10-minute expiry configured in bean definition)
- **isDuplicate**: checks cache, adds if absent
- **generateEventId**: uses SHA-256 content hash of `sessionId|pageUrl|timestamp` when all are present, otherwise UUID
- **generateContentHash**: `SHA-256(sessionId + "|" + pageUrl + "|" + timestamp)` → hex string

### 5. `GlobalExceptionHandler.java` — `@RestControllerAdvice`
- **MethodArgumentNotValidException** → 400 with field-level error messages
- **IllegalArgumentException** → 400 with exception message
- **Exception** → 500 with generic "Internal server error", logs the full stack trace

### Supporting Files
- **`SessionQueryService.java`** / **`HeatmapQueryService.java`** — interfaces in `com.track.collector` for the query endpoints (implementations provided by other modules)
- **`DataWriterService.java`** — interface in `com.track.writer` (writer module)
- **`SessionManagerService.java`** — interface in `com.track.session` (session module)
- **`pom.xml`** updated — added `visit-tracking-writer` and `visit-tracking-session` dependencies

### API 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/track/visit` | POST | 接收页面访问事件，异步写入 |
| `/track/heartbeat` | POST | 接收心跳事件（轻量级，不记日志） |
| `/track/click` | POST | 接收点击事件，坐标已换算为相对位置 [0,1] |
| `/track/session/{sessionId}` | GET | 查询会话详情（页面列表+停留时长+路径） |
| `/track/heatmap/{pageUrl}` | GET | 返回页面点击热力图数据（100×100 网格） |

### 核心数据流

```
前端埋点 → TrackController → EventCollectorService（校验+去重+预处理）
                                    ↓
                    DataWriterServiceImpl → Kafka Topic
                                                    ↓
                            KafkaConsumer → BatchWriteService → MySQL 分区表
```

### 关键设计决策

1. **会话管理**：Caffeine 本地缓存 + 30 分钟超时，5 分钟 IDLE 检测，定时任务每 5 分钟扫描
2. **去重策略**：SHA-256 内容哈希（sessionId + pageUrl + timestamp）+ Caffeine 缓存 10 分钟 TTL
3. **心跳机制**：前端 30 秒打点，后端更新 lastActiveAt，会话结束时以最后心跳时间估算离场时间
4. **路径还原**：按时间排序，referrer 为空时推断为前一页面，检测乱序事件标记 `outOfOrder`
5. **指纹算法**：UA + 分辨率 + 时区 + 语言 + 字体 → SHA-256，置信度加权评分（UA 0.3, 分辨率 0.2, 字体 0.2, 时区/语言各 0.15）
6. **数据存储**：visit_events / heartbeat_events / click_events 均按月分区，session 和 fingerprint 无分区
7. **Kafka 管道**：4 个 topic + 对应 DLT，手动 ACK，批量消费（500 条/次），3 并发
