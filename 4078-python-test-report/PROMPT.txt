用 Python 写一个多源测试报告聚合与分析平台，能够收集来自多个 CI 节点、多个并行任务的 JUnit XML 报告，进行合并、对比、趋势分析，最终生成一份结构化的 HTML 报告，并在控制台输出关键指标摘要。报告应覆盖单元测试、集成测试、端到端测试三个不同层级的结果。

工具在启动时通过命令行参数指定一个根目录，递归扫描该目录下所有 XML 文件，每个文件对应一个独立的 CI 工件。扫描过程中按文件名中的时间戳或构建号进行排序，便于后续趋势分析。对于每个 XML 文件，使用 xml.etree.ElementTree 解析，提取每个 testcase 的方法名、所属 class、耗时、失败堆栈，对于 failure 和 skipped 标签分别记录。

合并逻辑必须区分以下几种情况：第一，同一个测试套件在不同文件里出现（名字完全相同的 testsuite），这时候要把两边的用例合并到一起，重复的用例只保留一条记录，但失败标记取 OR 逻辑——只要任一文件里该用例失败，合并后就是失败。第二，同名但参数化测试不同的情况，比如 test_add[1+2=3] 和 test_add[4+5=6]，这两个在合并时要视为不同用例，合并后的套件要分别列出，不能合并。第三，跨文件的重复失败检测——同一个测试方法（完全限定的类名加方法名，如 tests.test_login.TestLogin.test_user_login）在两个不同文件里都失败了，要标记为"高频失败用例"，在报告中单独列出一节，并显示它失败了多少次、分别来自哪几个文件。

聚合报告的 HTML 页面要包含以下几个模块：顶部总览卡片（总用例数、总通过数、总失败数、总跳过数、整体通过率、累计耗时），中部按文件维度的通过率柱状图（用纯 HTML + CSS + 内联 SVG 实现，不需要第三方图表库），底部失败用例详情表（包含用例名、所在文件、失败消息、堆栈摘要），以及一个"重复失败"专区，列出所有高频失败的用例及其分布文件列表。每个失败的测试用例在 HTML 中要以红色背景行展示，鼠标悬停时显示完整堆栈信息。报告文件默认命名为 test_report.html，可通过 --output 参数自定义路径。

整体架构要求拆分为 4 个以上模块：主入口文件 report_aggregator.py 负责参数解析和流程编排；xml_parser.py 负责解析单个 XML 文件并返回结构化数据；report_merger.py 负责合并逻辑和重复检测；html_generator.py 负责生成 HTML 报告；trend_analyzer.py 负责趋势计算。每个模块职责单一，模块间通过明确的返回值传递数据，不共享全局状态。
