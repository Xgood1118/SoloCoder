用 Python 写一个 RSS 阅读器后端，支持订阅源管理、文章抓取、已读状态、标签分类和多格式输出，数据存储在 SQLite 里。

【背景描述】
个人或团队需要统一管理多个 RSS/Atom 订阅源，追踪技术博客、新闻站点、论坛帖子等更新，要求支持按类别分组、按标签筛选、已读未读过滤、抓取去重、后台定时同步，以及导出 OPML 格式方便迁移到其他阅读器。

【数据模型】
订阅源表（feeds）：id（主键自增）、url（唯一约束）、title（标题）、description（描述）、site_url（站点链接）、etag（HTTP ETag，用于 conditional GET）、last_modified（HTTP Last-Modified）、update_interval（更新间隔分钟，默认 30）、category（分类，默认为空字符串）、last_fetched_at（上次抓取时间）、error_count（连续错误次数）、is_active（布尔，是否启用，false 时不自动同步）。

文章表（articles）：id、feed_id（外键关联 feeds.id）、guid（全局唯一标识）、title、link（文章原始链接）、author（作者）、content（正文 HTML）、summary（摘要，截取前 300 字符）、pub_date（发布时间，datetime）、fetched_at（入库时间）、is_read（是否已读）、is_favorite（是否收藏）、is_starred（是否标星）、tags（标签列表，逗号分隔字符串）、read_at（已读时间）。注意 is_read 和 read_at 在更新时不能被覆盖——如果已读状态的文章被重新抓取（RSS 源重复推送），read_at 保持不变，不能改成未读。

分类表（categories）：id、name（唯一）、color（颜色代码，CLI 显示用）、sort_order（排序序号）。

【核心抓取逻辑】
抓取用 requests 库，每次请求带上 User-Agent（如果 User-Agent 为空字符串或 None，服务器可能会拒绝请求或返回错误页面，需要在发送前确保有默认值）和 If-None-Match/If-Modified-Since 头。如果返回 304 Not Modified 说明没有更新，跳过解析。如果返回 200 解析 XML（用 xml.etree.ElementTree），支持 RSS 2.0 和 Atom 1.0 两种格式。如果网络超时或解析失败，error_count 加 1，连续错误超过 5 次将该 feed 的 is_active 设为 false 并记录错误日志。

【去重策略】
入库前按 guid 去重——如果数据库中已有相同 guid 的文章就跳过，这是第一层去重。第二层去重：判断链接是否相同且 pubDate 在 30 分钟内，是则认为是同一条不重复插入。第三层去重是标题相似度检测：解析出 pubDate 后，如果两篇文章链接不同但 pubDate 相同（误差在 1 分钟内）且标题的相似度（用 difflib.SequenceMatcher）超过 0.8，认为是重复文章过滤掉。如果 pubDate 为空或解析失败，用当前时间作为 pubDate。

【Silent Failure 陷阱】
后台同步进程有定时器（用 threading.Timer 或 sched 模块），每 update_interval 分钟触发一次抓取所有活跃订阅源。这里存在一个静默失败陷阱：定时器触发时如果某个订阅源在 feeds 表中已不存在（如被删除但 Timer 对象仍持有旧引用），get_articles() 函数会抛出 KeyError 或 AttributeError 且被定时器吞掉，最终导致这一次同步任务静默失败，没有任何日志也没有错误提示。正确做法是在每次 Timer 执行时用 try-except 包裹，并在 except 块里至少打印一行警告日志，同时检查是否需要重新调度。

【级联删除】
删除订阅源时必须级联删除该 feed_id 下所有 articles 记录，以及该 feed 在 read_history（阅读历史表，如果有的话）中的记录。还要删除 category 中对应的 sort_order 占位（后续 feed 的 sort_order 自动前移）。

【CLI 接口设计】
命令格式类似：python rss_reader.py <command> [options]。主要命令：

feeds list：列出所有订阅源，显示 url、title、category、last_fetched、article_count、is_active 状态。用表格对齐输出，超过 20 个时自动分页。

feeds add <url>：新增订阅源（传入 URL），自动解析 RSS 并入库，返回 feed_id 和 title。如果 URL 格式不对或解析失败返回错误信息。

feeds remove <feed_id>：删除订阅源，级联删除文章，显示确认提示。

feeds update [feed_id]：手动触发抓取，支持单个 feed_id 或全部活跃 feed。

feeds import <opml_file>：批量导入 OPML 文件中的所有订阅源。

articles [options]：浏览文章，支持 --feed-id（按订阅源过滤）、--unread（只看未读）、--favorite（只看收藏）、--tag（按标签过滤）、--since <date>（只看某个日期之后）、--limit（每页数量，默认 20）、--offset（偏移量）参数。输出显示序号、标题、来源、pub_date、标签、已读/未读状态。

articles read <article_id>：标记文章为已读（同时设置 read_at），显示文章摘要和链接。

articles favorite <article_id>：切换收藏状态。

articles tag <article_id> <tags>：设置标签，tags 用逗号分隔。

articles export [--format csv|json] [--output file]：导出文章列表到文件。

search <keyword>：全文搜索标题和摘要，返回匹配文章。

stats：显示统计信息（总订阅源数、总文章数、今日新增、已读比例、各分类文章数）。

【模块划分】
至少 6 个模块：cli.py（命令行主入口和参数解析）、database.py（SQLite 初始化、Schema 定义、CRUD 操作）、fetcher.py（HTTP 请求、ETag 处理、重试逻辑）、parser.py（RSS/Atom 解析、去重逻辑）、sync.py（定时同步调度、Timer 管理）、export.py（OPML 导入导出、CSV/JSON 导出）。

【其他要求】
数据库路径从环境变量 RSS_DB 读取，默认 ./rss.db。初始化时自动创建表，不存在则新建。错误处理要详细——网络错误、解析错误、数据库错误分别捕获并给出有意义的提示。CLI 帮助信息要完整，每个命令都有 --help 说明用法。
