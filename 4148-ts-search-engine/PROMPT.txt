# TypeScript/Node.js 搜索引擎

这次要做一个全文搜索引擎，TypeScript 加 Node.js 技术栈，主要是对结构化的文本内容进行索引和搜索。说实话开源的 Elasticsearch 很强大，但是部署维护成本高，内存占用大，运维人员要专门学这套技术栈，有些小团队或者简单场景其实不需要那么重的方案。自己做一个轻量级的搜索引擎反而更合适，可以针对性地优化满足特定业务需求，比如垂直搜索、站内搜索这类场景，数据规模在百万级文档量级的时候，这个方案要能稳定运行并保持不错的搜索质量。

索引构建是核心功能，要支持从数据库或者文件导入数据建立索引，导入过程要能增量，就是只处理新增和变化的数据不用全量重建。倒排索引的数据结构要设计好， postings list 里面要能存储词频、位置、文档频率这些信息，这样才能支持后续的相关性计算。分词器是搜索质量的基础要做扎实，中文分词是难点，可以用结巴分词库或者庖丁分词库，分词效果差搜索体验就差，词库要能热更新不用重启。英文分词要能处理大小写转换统一转小写、词干提取比如 running 还原成 run、停用词过滤比如 the is a 这种无意义词。分词器要可扩展，能接入不同的分词算法或者字典，用户要能指定字段权重比如标题命中的权重高于正文命中。

搜索功能要支持多种查询类型，精确匹配、模糊匹配、范围查询、多字段联合查询这些基本能力要有。短语搜索要支持，就是引号包起来的连续词组要作为一个整体来匹配，比如搜索 "机器学习" 要作为一个完整短语而不是把机器和学习分开。布尔查询要支持 AND、OR、NOT 操作符，搜索语法要符合搜索引擎的常见用法比如加减号表示必须包含和排除，可以简单解析一下类似 Google 的搜索语法。分页功能要做，每页返回多少条、跳到第几页要支持，但是深度分页要有限制比如最多只能翻到第 1000 条，防止 from + size 过大导致内存问题，超过限制要报错或者提示用游标。

相关性排序是搜索质量的关键，要能基于词频、文档频率、字段权重来计算相关性得分比如 TF-IDF 算法，也要能支持自定义排序规则比如按发布时间倒序、按热度分数排序、按销量排序。高亮显示要做，搜索关键词在结果里要能高亮标出来用 em 标签包裹，让用户一眼看到匹配的位置。搜索建议和自动补全要做，当用户输入的时候能给出搜索建议比如输入 "机器" 能提示 "机器学习"、"机器视觉"，这个可以用前缀树或者 n-gram 模型来实现，响应要在毫秒级不然体验很差。要能记录用户的搜索历史和热门搜索词汇，给运营分析提供数据支撑。纠错功能要有，搜索 "机器字习" 要能智能纠错成 "机器学习"，拼音模糊搜索也要支持比如搜索 "jqx" 能找到包含 "机器" 的结果。

性能方面要充分优化，索引要支持增量更新，不用每次都全量重建，索引分片和副本要能配置支持。要有缓存机制，重复的搜索请求要能命中缓存返回，比如热词搜索结果要能缓存一段时间。要能支持分布式部署，多个节点共同承担搜索请求和索引更新，节点之间要能同步索引数据。监控指标要完善，索引文档数、搜索延迟、缓存命中率这些都要能监控到，要有健康检查接口。单元测试要覆盖分词准确性、搜索相关性排序、各种查询语法这些核心功能，边界条件比如空搜索串、特殊字符转义、超长查询词也要有测试。
